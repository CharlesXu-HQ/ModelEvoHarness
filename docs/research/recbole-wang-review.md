# RecBole and industrial recommendation notes: incremental value for ModelEvoHarness

Reviewed against the [current FunRec coverage map](../source-coverage.md) and [catalog](../../src/model_evo_harness/data/catalog.json), pinned to FunRec `5f7bd84d4403b5f92b6bedbd31e3984ef00a4572`. Primary sources: [RecBole repository at `7b02be5`](https://github.com/RUCAIBox/RecBole/tree/7b02be5ec80a88310f2d04a27a82adfcbb5dc211) and its official [v1.2.1 documentation](https://recbole.io/docs/); [Wang Shusen's RecommenderSystem at `8c8796c`](https://github.com/wangshusen/RecommenderSystem/tree/8c8796c560c13059b19b51f5b5b963137f4ef287). The recommendations below are **our proposed harness behavior**, not claims that either source implements this Agent harness. No upstream code, slides or prose should be copied into the package.

## Overlap and actual additions

| Source concept | Already represented from FunRec | Non-overlapping value for an Agent experiment | Preconditions and boundary |
| --- | --- | --- | --- |
| RecBole's general, context-aware, sequential and knowledge-based model groups ([model introduction](https://recbole.io/docs/user_guide/model_intro.html)); its typed interaction, user, item, knowledge graph and item-link files ([atomic files](https://recbole.io/docs/user_guide/data/atomic_files.html)) | `collaborative_retrieval`, `feature_interactions`, `interest_retrieval`, `item_representation` and `sequence_ranking` cover most named architectures. | A *typed side-information contract* for knowledge-graph candidates is new: verify that entity/relation triples and item-entity links exist, are usable at the prediction cutoff, and are joined correctly before proposing a KG ablation. This is not the same as FunRec's item co-occurrence/EGES graph mechanism. | Requires a genuine item catalog, KG triples and item links. A coupon RCT with one binary action cannot run it. Do not add dozens of duplicate model cards simply because RecBole lists them. |
| RecBole's `group_by`, random/temporal `order`, ratio/leave-one-out `split`, and full/uniform/popularity-sampled/labeled evaluation modes ([evaluation settings](https://recbole.io/docs/user_guide/config/evaluation_settings.html)); preservation of predefined benchmark splits ([data settings](https://recbole.io/docs/user_guide/config/data_settings.html)) | `task_framing` freezes split/metric; journal identity includes task and dataset. | Define an **evaluation-protocol signature** in the host snapshot: unit, cutoff/order, split assignment, candidate universe, evaluation mode, negative sampling, metric `k`, target and preprocessing. The Agent may compare scores or reuse lessons only under a compatible signature. Prefer a supplied fixed split over a newly generated one. | Requires host-provided metadata; do not infer ordering or exposure from column names. A full-ranking score and a sampled-negative score are different estimands. This signature supplements the dataset fingerprint. |
| RecBole distinguishes observed explicit labels from implicit interactions, where unobserved items become sampled negatives ([label of data](https://recbole.io/docs/user_guide/data/label_of_data.html)); Wang distinguishes retrieval-stage negatives and warns about using exposed-but-unclicked examples as retrieval negatives ([retrieval negatives slides, pp. 5–20](https://github.com/wangshusen/RecommenderSystem/blob/8c8796c560c13059b19b51f5b5b963137f4ef287/Slides/02_Retrieval_07.pdf)) | `feedback_bias` notes exposure/selection bias, but does not spell out negative-label semantics by stage. | Add an Agent check before changing a loss or sampler: name the *source of negatives*, sampling distribution and target stage; keep the evaluation candidate universe fixed. A negative-sampling change is an experiment in its own right, with popularity/coverage and calibration diagnostics. | Requires interaction/exposure logs for retrieval or ranking. The stronger stage-specific warning comes from the lecture; it is not a universal proof that every unclicked exposure is useless. A randomized treatment/control outcome must never be reinterpreted as a sampled user-item negative. |
| RecBole exposes parameter search spaces while retaining a fixed configuration ([parameter tuning](https://recbole.io/docs/user_guide/usage/parameter_tuning.html)) | Agent already proposes and records bounded trials; model architecture iteration exists. | Record search-space boundaries and the *axis changed* in each proposal, then compare an architecture change to a matched-capacity or simple tuned baseline before claiming a structural win. Budget and split remain fixed. | This is mostly a stricter protocol for existing behavior, not a new model family or a dependency on RecBole/Hyperopt/Ray. |
| Wang separates multiple predicted outcomes from the **score-fusion decision** ([score fusion slides, pp. 2–7](https://github.com/wangshusen/RecommenderSystem/blob/8c8796c560c13059b19b51f5b5b963137f4ef287/Slides/03_Rank_03.pdf)) | `multiobjective` covers shared-bottom, MMoE, PLE and related prediction architectures. | Offer a distinct decision-layer hypothesis: with the same predictions, compare business-value score formulas, constraints and thresholds; diagnose whether gains arise from prediction or action selection. In coupon use, compare incremental outcome against cost only if both have valid observed definitions. | Requires calibrated or consistently scaled outcome estimates, declared business objective, and any cost/price fields. A score formula does not establish causal uplift by itself. |
| Wang's cold-start and special-population work describes traffic allocation ([cold-start traffic slides, pp. 2–20](https://github.com/wangshusen/RecommenderSystem/blob/8c8796c560c13059b19b51f5b5b963137f4ef287/Slides/07_ColdStart_05.pdf)) and pooled-model residual correction/calibration for special cohorts ([special populations slides, pp. 3–21](https://github.com/wangshusen/RecommenderSystem/blob/8c8796c560c13059b19b51f5b5b963137f4ef287/Slides/08_Improvement_05.pdf)) | `cold_start` and `multiscenario` flag cohort support and differentiated mechanisms. | Before escalating to separate models, test **predeclared slice calibration / residual correction** against the pooled baseline, with cohort support, primary metric and maintenance cost. Treat traffic allocation as a policy hypothesis distinct from fitting a new model. | Needs a meaningful pre-outcome cohort and adequate sample. Content traffic guarantees need a dynamic exposure/capacity process; not directly testable on a static coupon RCT. Lecture examples are illustrative, not transferable performance estimates. |
| Wang's reranking rules describe position/spacing caps and MMR under feasible-item filtering ([reranking rules slides, pp. 2–7](https://github.com/wangshusen/RecommenderSystem/blob/8c8796c560c13059b19b51f5b5b963137f4ef287/Slides/06_Rerank_03.pdf)) | `slate_reranking` covers relevance/diversity and fixed slate size. | Explicitly model **hard feasibility constraints** separately from soft diversity/relevance weights. Compare policies on the same candidate set and audit infeasible slates plus utility. | Needs candidate slates, item attributes and position rules. Not applicable to a single binary coupon decision. |
| Wang covers layered A/B tests, holdouts and reversal tests ([A/B slides, pp. 3–22](https://github.com/wangshusen/RecommenderSystem/blob/8c8796c560c13059b19b51f5b5b963137f4ef287/Slides/01_Basics_03.pdf)); its cold-start experiment discussion shows user-side and creator-side competition/interference ([cold-start A/B slides, pp. 2–18](https://github.com/wangshusen/RecommenderSystem/blob/8c8796c560c13059b19b51f5b5b963137f4ef287/Slides/07_ColdStart_06.pdf)) | `feedback_bias` and `production_lifecycle` mention causal support and offline-online gap. | Add an **interference and rollout note** to a hypothesis when decisions share scarce inventory, creator traffic, budget or user exposures. State randomization unit, competing actors and why a fixed-data offline effect might fail after rollout. Ask for an online design instead of claiming offline proof. | Requires a future online experiment; it should not change the present offline evaluator or silently turn cross-user dependence into an independent-row assumption. |

## Recommended implementation order

1. **Protocol compatibility gate (highest value).** Let adapters declare evaluation mode, split/cutoff, label provenance, negative source and candidate universe; hash these in journal identity and return a specific mismatch reason. Test that an Agent cannot compare full ranking with sampled ranking or change a presplit benchmark mid-search. This directly changes experiment validity across recommendation/search/ads. Sources: [RecBole evaluation](https://recbole.io/docs/user_guide/config/evaluation_settings.html), [benchmark split](https://recbole.io/docs/user_guide/config/data_settings.html), [labels](https://recbole.io/docs/user_guide/data/label_of_data.html).
2. **Decision-layer and cohort hypotheses.** Add portable proposal guidance and validation for score-fusion/threshold/constraint changes and slice calibration/residual correction, with an unchanged predictor as the control where appropriate. This gives the Agent a route beyond endless architecture or learning-rate changes. Require actual fields and a falsifying test. Sources: [fusion](https://github.com/wangshusen/RecommenderSystem/blob/8c8796c560c13059b19b51f5b5b963137f4ef287/Slides/03_Rank_03.pdf), [cohorts](https://github.com/wangshusen/RecommenderSystem/blob/8c8796c560c13059b19b51f5b5b963137f4ef287/Slides/08_Improvement_05.pdf).
3. **Data-conditional research directions.** Make KG side information and hard slate constraints discoverable only if typed triples/links or slates/rules are available. Add negative-sampling proposals only in implicit-feedback tasks; mark an RCT coupon task ineligible. Sources: [RecBole atomic files](https://recbole.io/docs/user_guide/data/atomic_files.html), [Wang reranking](https://github.com/wangshusen/RecommenderSystem/blob/8c8796c560c13059b19b51f5b5b963137f4ef287/Slides/06_Rerank_03.pdf), [Wang negatives](https://github.com/wangshusen/RecommenderSystem/blob/8c8796c560c13059b19b51f5b5b963137f4ef287/Slides/02_Retrieval_07.pdf).
4. **Online-design warning, not an offline metric.** Carry interference and randomization-unit questions into the report/data request when shared inventory or budgets exist. Source: [Wang A/B](https://github.com/wangshusen/RecommenderSystem/blob/8c8796c560c13059b19b51f5b5b963137f4ef287/Slides/07_ColdStart_06.pdf).

## Deliberately excluded

- Re-listing RecBole's CTR, CF, two-tower or sequential architectures already represented in the FunRec map. A model list alone would not improve experiment choice.
- Bundling RecBole or copying code/config examples. Its useful protocol ideas are independent of a runtime dependency.
- Treating Wang's online A/B setup, Bloom-filter exposure service ([exposure-filter slides](https://github.com/wangshusen/RecommenderSystem/blob/8c8796c560c13059b19b51f5b5b963137f4ef287/Slides/02_Retrieval_12.pdf)) or creator-traffic mechanisms as validated by CouponEvo's static public datasets.
- Choosing a model by reported benchmark rank or adding its published hyperparameter ranges as universal defaults. Dataset, target, split and evaluation mode must match first.
