# Harness 系统核验与探索效率改进

日期：2026-10-05。审计基线为 ModelEvoHarness `544badf`、CouponEvo `fbc13f0`；本文件同时记录本轮修复。用户确定的优先目标是：**先提高有效假设与实验的产出**。验证集冠军用于继续探索，独立验证结论另行判断。

## 结论

已检查五组技术来源和三个编排参考。原有“覆盖完整”的表述需要收紧：**FunRec 固定版本的路径映射完整，不等于所有上游模型、训练流程或论文机制均已实现。** 本地有 44 张方法卡的 PyTorch/TensorFlow 参考核心（另有通用 TwoTower），并非 44 套可直接用于任意数据集的完整训练系统。

最明显的断点是：源码已经存在，API Agent 先前却只能读取签名；模型省略的原方法机制也没有机器可读的声明。这两项已修复，并接入 CouponEvo。仍需优先补足的是宿主提供的诊断证据、可执行训练配方、试验比较记录和失败分类。不能据本轮单元测试声称 Agent 已有更高的真实优化成功率。

## 本轮已完成

1. **源码获取进入真实调用链。** 内置 Agent 可先返回 `read_reference`，宿主提供完整本地模型模块、共享辅助类和可选训练代码，再让 Agent 生成候选。声明已收录 `method_id` 却未读源码时会自动补读。每提案最多两轮，限制总内容大小，并记录实际 SHA-256；CouponEvo 的提案纠错不会重置额度或丢失已读内容。
2. **实现边界交给 Agent。** 90 个框架入口均有 `reference_scope`、`training_support`、`output_contract`、`limitations`，并进入 `model_api` 和源码返回。DIEN 的辅助目标、HSTU 的系统边界、DCNv2 的专家混合等不再隐含为已支持。
3. **通用知识确实被读取。** 22 篇家族指南之外，8 篇通用指南进入上下文，包括训练目标、优化、困难样本、数据请求、业务经验，以及新增探索策略、结构扩展、随机营销实验适配。源码无需依赖外部网址获取。
4. **修复不必要的探索阻塞。** 困难负采样按反馈语义区分观测负例和采样未观测项；缺曝光不自动禁止所有召回实验。CouponEvo 拒绝请求已存在字段，领域前提必须匹配实际来源与时点。分析调用最多重试一次，复用已评估结果，不额外训练。
5. **正常分析使用 high。** 通用供应商的正常反思使用迭代配置，宿主显式 `review_required` 时才使用复核配置；CouponEvo 原有异常复核逻辑保留。
6. **文档如实描述能力。** 中英文 README、模型和接入文档同步说明参考实现、训练责任、源码读取和未完成能力。

新指南：[探索策略](../../src/model_evo_harness/knowledge/exploration_strategy.md)、[结构扩展](../../src/model_evo_harness/knowledge/structure_extensions.md)、[随机营销实验](../../src/model_evo_harness/knowledge/causal_policy_experiments.md)。新增方法是开放研究方向，不能仅凭名称或 `ready` 状态预期收益。

## 尚未补齐：按探索产出排序

| 顺序 | 实质缺口 | 建议验收方式 |
| --- | --- | --- |
| 1 | **可计算的诊断与可执行配方。** 当前很多要求是说明文字；只有一个总体分数时，Agent 无法区分欠拟合、过拟合、优化失败、标签偏差、成本分配问题。 | 宿主返回训练曲线/停止原因、支持度、分组误差、校准、行动和成本统计；缺项明示原因。先打通一个完整 coupon-uplift 配方和一个检索配方，校验输入、loss、mask、负例、GPU 和评估接口后才运行。 |
| 2 | **实现故障与基础设施故障分开。** 通用 runner 的异常诊断过粗；临时 API/GPU/文件错误可能消耗研究预算。 | 同一 trial 有限重试服务故障；确定的代码错误反馈位置和类型；核验无需重复训练、不会无限循环。保留所有失败作为效率统计。 |
| 3 | **对照与经验的可比性。** 文字说“只改一个机制”不足以保证实际代码遵守；历史业务经验有时只有解释，没有完整数值证据。 | 每次保存 control、实际变更轴、数据/协议/代码摘要、预算和运行统计。回放附原基线、指标、支持度与不确定性；语义相近的机制名称不当作独立创新。 |
| 4 | **方向特有的完整机制。** 部分 loss、采样和序列模型只有核心代码或设计；图传播、部分新结构和生成式推荐未实现。 | 由实际诊断决定下一实现，完成输入→训练→评估→消融，而不是扩大名字数量。新实现继续分 PyTorch/TensorFlow，禁止借助第三方包装模型冒充独立实现。 |
| 5 | **业务解释与停止理由。** 合法 observation ID 不证明自由文本解释正确；两个不同机制只是数据请求的最低格式门槛。 | 业务判断携带结构化人群、估计和限制；普通停止说明当前替代假设为何不成立。预算耗尽记录仍值得尝试的下一假设。 |

跨场景是适配目标。搜索需要 query/document 角色和按 query 的评估协议；广告需要其曝光、转化、成本或竞价契约。不能只把 stage 标签改成 ready，就声称已完成这些场景的端到端接入。

## 如何验证探索效率

使用相同完整公开数据、GPU、Agent 模型/推理配置、初始候选、数据切分、候选预算和评价口径，对照旧版与新版；记录 API 消耗和 GPU 时间。既有已查看过的测试集不能重新被称为 untouched holdout。

优先报告：候选完成评估比例、实现错误类型和修复率、每单位资源产出的有效对照、反思对下一假设的实际影响、非重复机制的内容审核。提前停止/请求数据/失败都属于结果。验证集分数用于选择探索冠军；最终收益结论另走保护留出集与正确的配对估计。方法数量、指南数量和一次随机 Agent 运行都不能估计稳定成功概率。

本轮验证是接口、模型参考契约与集成回归；没有运行新的真实数据 GPU A/B，不作性能提升结论。

回归记录：ModelEvoHarness 全套测试 **90 passed、212 subtests passed**；48 条既有 TensorFlow/gast 与 Python 3.13 的弃用警告。`catalog-check` 通过，模型入口及本地文档链接检查通过。源码读取、跨框架拒绝、读取额度跨纠错保留、正常/异常反思 effort 均有回归覆盖。
