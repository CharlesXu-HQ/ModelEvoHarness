# FuxiCTR model structures: incremental value for ModelEvoHarness

## Scope and evidence

Source review dated 2026-11-12. FuxiCTR is pinned to `183da1c944ba8930fcdcd54114837c081959d748`; Harness is pinned to `0888cd51c184a64da81d75e858d6671a4dc8b72d`, including DANet. The full README inventory screening is in [the inventory note](fuxictr-inventory-2026-11-12.md). This note deeply inspects the shortlisted model implementations and their closest local computations. Names alone are not treated as evidence of a mechanism gap.

The intended use is Agent-led changes inside a fixed host backbone, with horizontal branches when justified, and independent native PyTorch and TensorFlow components. No FuxiCTR dependency, BaseModel wrapper, feature map, trainer, or whole-model replacement is proposed. No training experiments, accuracy comparisons, runtime benchmarks, or execution tests were performed; the priorities below are engineering judgments from source inspection, not evidence of task-specific lift.

Existing local evidence used throughout:

The practical first batch is gated cross, one MaskBlock, and reusable branch fusion; WuKong is the next distinct token interaction family. FmFM/FLEN or EDCN can move ahead when supported field groups or existing complementary cross/deep streams make them more relevant. This order favors isolated comparisons and interface reuse, not expected leaderboard gains.

## Models that need careful deduplication

### FinalNet is primarily a composition recipe here

[FactorizedInteraction](https://github.com/reczoo/FuxiCTR/blob/183da1c944ba8930fcdcd54114837c081959d748/model_zoo/FinalNet/src/FinalNet.py#L266) projects `x` into `h2,h1`, then returns either `h2 + h1*h2` or `concat(h2,h1*h2)`. This is a useful explicit multiplication placement, but the sum form is already expressible exactly as the local `LatentCross(hidden=W2(x), context=x)` with its context affine map set to `W1`. The concat form is an equally small composition around the same product. [ConditionalSwiGLU](../../src/model_evo_harness/models/pytorch/paper_unified_sequence.py#L37) is another nearby gated-product family, with different activation and sequence semantics.

Therefore add a clear composition recipe or a small convenience block only if it improves Agent usability; do not count a wholly new mathematical mechanism. Upstream two-block FinalNet averages logits and adds detached-ensemble consistency losses. Those losses change training and should remain a separate optional experiment from the interaction-layer comparison. The [FINAL paper](https://www.ruizhang.info/publications/SIGIR%202023%20Short_FINAL.pdf) motivates a factorized interaction layer; neither its benchmark results nor a polynomial-degree argument establish a gain for the host task.

### APG is already present; reusable conditional layers are the increment

Local APG has learned input/output projections and a scenario-generated `rank×rank` center matrix. Upstream [APG_Linear and APG_MLP](https://github.com/reczoo/FuxiCTR/blob/183da1c944ba8930fcdcd54114837c081959d748/model_zoo/APG/src/APG.py#L24) additionally expose full-matrix generation, generated bias, low-rank factorization with optional overparameterized U/V factors, and repeated conditional hidden layers. Self-wise mode conditions on the current layer input; group-wise/mix-wise modes consume an external condition inside APG_MLP.

A standalone `(hidden, condition) -> hidden_out` adapter could improve fixed-backbone use; a second APG model entry would mostly duplicate the installed core. Prioritize a concrete condition mismatch or subgroup residual before adding generated full matrices or more hypernetwork capacity. Merely using one global scenario label does not establish a need for sample-wise dynamic parameters.

### PPNet overlaps PEPNet, and the upstream PEPNet file is a stub

Local PEPNet already has EPNet-style input scaling and per-task PPNet-style hidden scaling. Upstream [PPNet_MLP](https://github.com/reczoo/FuxiCTR/blob/183da1c944ba8930fcdcd54114837c081959d748/model_zoo/PEPNet/src/PPNet.py#L109) uses a separate two-layer GateNU at each hidden depth, with `concat(stop_gradient(feature_emb), gate_prior_embeddings)` as gate input. This extends local one-stage context-only hidden gating by depth, prior conditioning and an explicit gradient boundary. These are meaningful variants, not an absent PPNet family.

At the pinned commit [PEPNet.py](https://github.com/reczoo/FuxiCTR/blob/183da1c944ba8930fcdcd54114837c081959d748/model_zoo/PEPNet/src/PEPNet.py) contains only `# Todo`. FuxiCTR's implemented model here is PPNet; do not infer full PEPNet support from its directory name or credit it with capabilities already present locally.

### QNN-alpha is implemented, but isolate its computation from self-ensemble training

The directory has two distinct files. [QNN.py](https://github.com/reczoo/FuxiCTR/blob/183da1c944ba8930fcdcd54114837c081959d748/model_zoo/QNN/src/QNN.py) contains T1–T30 neuron variants, many close to existing bilinear, LatentCross, and affine-product constructions. [QNN_alpha.py](https://github.com/reczoo/FuxiCTR/blob/183da1c944ba8930fcdcd54114837c081959d748/model_zoo/QNN/src/QNN_alpha.py) actually implements the multi-head/multi-row projected-product block and double training forward passes. Its layer splits embedding coordinates into heads, projects the flattened input into multiple rows with ReLU, multiplies corresponding entries, sums rows and adds the input residual. Its training loss supervises the mean probability and uses the detached mean as consistency target for each pass; evaluation uses one pass.

Thus the [paper's multi-head Khatri–Rao and self-ensemble claims](https://arxiv.org/abs/2505.17999) are not merely README promises. Still, the structural novelty relative to local multiplicative gates is the head/row parameterization and placement. Keep QNN-alpha behind simpler gated-product controls; do not import all neuron variants or conflate the training loss with architectural lift. The source reshaping requires compatible field/embedding/head dimensions even though this is not comprehensively validated there.

## Paper claims versus the pinned executable source

- **GDCN:** the [paper](https://arxiv.org/abs/2311.04635) describes both gated crossing and field-level dimension optimization (FDO). The inspected FuxiCTR GDCN directory implements the gated cross models; it does not implement the paper's learned FDO procedure. Generic feature-specific embedding widths in the framework are not equivalent to learned FDO.
- **FinalMLP:** [the paper](https://arxiv.org/abs/2304.00902) and source both support feature gates and bilinear fusion. The code calls `num_heads` attention heads in docstrings, but the fusion computation is headwise bilinear multiplication, not softmax attention. With no context fields the gate is global and learned.
- **EDCN:** the pinned attention bridge constructs attention1 and attention2, but its forward uses `attention1` for both streams. Treat a two-independent-gate implementation as a deliberate corrected design, not a literal reproduction of that path. This is static inspection, not a reproduced runtime failure.
- **WuKong:** the concrete FMB uses `X(XᵀP)` or a full Gram fallback and emits new tokens with an MLP. This is a source-backed computational distinction; no scaling-law, universal transfer or speed result was measured in this review.
- **MIRRN:** the source retrieves target, recent-mean and global-mean views, adds recency positions, filters them with FFT blocks, pools and uses target attention. Retrieved masks are returned but not passed into FilterLayer2 or its subsequent mean. `einsum("blnd,ndd->blnd", A, B)` selects only diagonal elements of the nominal block matrices; it does not perform full dense within-block channel mixing. Native adaptation must explicitly define padding and frequency semantics instead of assuming paper-level MHFT equivalence. Existing [DANet DiscountPreferenceBranch](../../src/model_evo_harness/models/pytorch/discount_aware.py) already uses FFT filtering, but on regular discount histories with a different transformation and purpose, so FFT alone is not new.

## Remaining inventory: conditional research, not a backlog of mandatory models

The full inventory note distinguishes existing native cores, guidance-only methods and missing dedicated entries. Beyond the shortlist:

- **FFM/ONN and FGCNN/CCPM:** already described in local guidance. Partner/operation-specific embeddings change parameter sharing and storage; convolutional feature generation depends on a justified field ordering. These are optional representation-side interventions, less naturally isolated than a hidden-state operator.
- **AFN/EulerNet:** [AFN's log/exp learned interaction orders](https://github.com/reczoo/FuxiCTR/blob/183da1c944ba8930fcdcd54114837c081959d748/model_zoo/AFN/src/AFN.py#L121) and [EulerNet's magnitude/phase interactions](https://github.com/reczoo/FuxiCTR/blob/183da1c944ba8930fcdcd54114837c081959d748/model_zoo/EulerNet/src/EulerNet.py#L139) are more distinct algebraic hypotheses. They bring numerical/sign/normalization choices and should follow evidence that simpler product/cross branches miss a supported interaction pattern.
- **FiGNN, SAM, AOANet, DESTINE, InterHAt:** field-graph propagation, alternative pair/vector aggregation and attention decomposition remain useful mechanism references, but Harness already has attention, graph and token-interaction families. Select the exact missing relation/update before adding any named model. A graph over feature fields is not automatically equivalent to existing user-item graph encoders.
- **HOFM, HFM, LorentzFM, DeepIM, DLRM:** higher-order FM, circular interactions, hyperbolic geometry and alternative interaction composition merit task-specific screening; a missing dedicated entry is not evidence that the current host cannot express its useful sub-computation. DLRM's dense/categorical interaction composition particularly overlaps existing embeddings, dot products and MLPs.
- **BST, DMIN, DMR:** first resolve the gap relative to existing SASRec, TransAct, DIN/DIEN, multi-interest and contextual-history blocks. New history assumptions or auxiliary labels are not supplied merely by a model implementation.

## Native component contract for a future implementation pass

Use tensor-first PyTorch `nn.Module` and TensorFlow `Layer`/`Model` APIs with explicit input/output dimensions, field groups and optional masks. Return representations or raw scores and let the host own embeddings, objective and optimizer. Reuse the current composition/evidence interfaces; add only the method cards and knowledge needed to explain when a block differs from existing ones.

Verify each selected mechanism through formula-level reference examples, meaningful gradients and mask behavior when applicable, plus cross-framework numerical agreement with mapped weights. Keep data, backbone, split, objective and resource budget fixed for structural comparisons; separately declare auxiliary losses, changed embeddings or parameter sharing. None of these proposed verification or task experiments was run during this read-only review.
