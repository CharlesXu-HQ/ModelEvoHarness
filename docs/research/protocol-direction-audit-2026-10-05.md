# RecBole and industrial recommendation: residual gaps for Agent experiments

Audit date: 2026-10-05. This is a comparison of ModelEvoHarness with the current official [RecBole documentation](https://recbole.io/docs/) and [Wang Shusen's course index](https://github.com/wangshusen/RecommenderSystem), including linked lecture material. The older [incremental review](recbole-wang-review.md) supplied useful questions; this audit checks what the **current implementation** now does. Upstream evidence motivates experiments, not a claim that those projects implement this Agent harness. Recommendations below are design inferences, not measured gains.

## What exists, and where the boundary is

The repository has original, compact PyTorch and TensorFlow cores for 44 method cards, plus a generic two-tower example; [model documentation](../models.md) explicitly limits them to mechanism references, not complete paper reproductions or production systems (lines 3–5, 23–34, 63–70). The Agent receives applicability reports, local guides, baseline, trial history and model APIs ([engine.py](../../src/model_evo_harness/engine.py), lines 269–345). It can read full bundled model/training modules before proposing a trial ([provider.py](../../src/model_evo_harness/provider.py), lines 13–65). That is substantive working material, rather than a mere bibliography or model-name index.

The host task still owns real rows, feature construction, training, candidate sets, constraints, metrics, uncertainty and the final holdout ([adapter-contract.md](../adapter-contract.md), lines 3, 28–41; [models.md](../models.md), lines 63–70). The Agent can lead hypothesis selection and reflection only to the extent that an adapter supplies diagnostic evidence and executable candidate operations. None of the upstream systems changes this host boundary. In particular, having a model reference or a `ready` card does not demonstrate that a trial is trainable, fair, or beneficial on the host dataset.

## Findings ordered by expected value to exploration

### 1. Diagnostic evidence is not yet a machine-readable prerequisite for hypothesis choice — high

**Local evidence.** `_evaluation` requires a finite `score` and a `metrics` dictionary, but no training curve, cohort support, error slice, calibration table, retrieval coverage, or trial resource receipt ([engine.py](../../src/model_evo_harness/engine.py), lines 92–115). `validate_research` requires nonempty `why_now`, `comparison` and `falsification` strings, but cannot verify that a cited symptom exists in the baseline or history ([catalog.py](../../src/model_evo_harness/catalog.py), lines 411–429). The new [exploration strategy](../../src/model_evo_harness/knowledge/exploration_strategy.md) tells the Agent to request a diagnostic report from existing data (lines 5–10); this is now good guidance, not yet an adapter contract.

**Upstream evidence.** RecBole exposes evaluation mode and a wide set of ranking, coverage and value metrics in its [evaluation settings](https://recbole.io/docs/user_guide/config/evaluation_settings.html), while its [training settings](https://recbole.io/docs/user_guide/config/training_settings.html) expose sampler and training controls. Wang's [course index](https://github.com/wangshusen/RecommenderSystem) separates retrieval, ranking, diversity, cold start and special populations; these imply different diagnostic slices. **Inference:** an Agent choosing among those mechanisms needs observations that discriminate them, not just a global score.

**Minimal completion.** Have the host return a small, versioned `diagnostics` record for baseline and each trial: the objective's evaluation unit/support, per-slice metric with denominator, train/validation trend or stop reason, calibration when probabilities drive decisions, and stage-specific coverage/latency or action/cost usage. Include explicit `unavailable` reasons. Permit an Agent `request_diagnostics` action that computes only from existing frozen data; do not turn an absent diagnostic into a request for new fields. Test that a proposed mechanism's `why_now` cites a concrete diagnostic key or prior trial ID. This should be an adapter protocol, not dozens of new cards.

### 2. The protocol fingerprint is present, but trial comparability remains delegated to the host — high

**Local evidence.** A task may omit `evaluation_protocol`; when present, validation checks only a few required nonempty strings, with `candidate_universe` conditional on retrieval/reranking and `negative_source` on implicit feedback ([engine.py](../../src/model_evo_harness/engine.py), lines 77–87). The whole snapshot and optional protocol are fingerprinted for resume ([engine.py](../../src/model_evo_harness/engine.py), lines 290–313). `task.evaluate(proposal, trial_dir)` returns only score/metrics as mandatory output, so a trial does not prove that it actually used the declared split, label horizon, candidate universe, K, sampler, prediction cutoff, or metric implementation ([engine.py](../../src/model_evo_harness/engine.py), lines 372–392). [adapter-contract.md](../adapter-contract.md) states this enforcement is the host's job (lines 37–41).

**Upstream evidence.** RecBole explicitly distinguishes grouping, random versus temporal order, split, and full/uniform/popularity-sampled/labeled evaluation ([evaluation settings](https://recbole.io/docs/user_guide/config/evaluation_settings.html)); it also supports benchmark split configuration ([data settings](https://recbole.io/docs/user_guide/config/data_settings.html)). Its [significance-test workflow](https://recbole.io/docs/user_guide/usage/significance_test.html) compares like experiments. **Inference:** two scores with different unit, candidate universe or label horizon need separate interpretation even if the dataset bytes match.

**Minimal completion.** Require a canonical host protocol for new integrations: unit and grouping, split IDs/cutoff, target/label horizon, candidate universe and evaluation mode, top-K/denominator, preprocessing version and metric code/version, plus treatment/propensity rules where relevant. Store a host-produced **trial receipt** that repeats the protocol digest, row/unit counts, model/data artifact digests and evaluation mode; reject a receipt mismatch before updating the exploratory champion. Older adapters may remain compatible but should be labeled `protocol_unverified`. Do not imply the harness can inspect private data or independently validate host metric code.

### 3. A controlled comparison is written in prose but has no executable change boundary — high

**Local evidence.** `research.comparison` is required, while `candidate` is any non-null host-defined JSON value ([engine.py](../../src/model_evo_harness/engine.py), lines 204–228; [catalog.py](../../src/model_evo_harness/catalog.py), lines 411–451). The framework checks the method's declared stage/capabilities, not whether the submitted candidate changed exactly one intended axis or used matched compute ([catalog.py](../../src/model_evo_harness/catalog.py), lines 355–373). The provider asks for one mechanism and fixed protocol ([provider.py](../../src/model_evo_harness/provider.py), lines 69–108), which is useful guidance but not a verified comparison.

**Upstream evidence.** RecBole separates fixed configuration from search-space parameters and objectives in [parameter tuning](https://recbole.io/docs/user_guide/usage/parameter_tuning.html). Its [training settings](https://recbole.io/docs/user_guide/config/training_settings.html) make optimizer, sampler, update budget and stopping controls explicit. **Inference:** apparent architecture gains can instead come from unequal search or training budget.

**Minimal completion.** Ask the host adapter to return a resolved candidate/config digest, control ID, actual changed keys, seed/update/compute budget and training/evaluation receipt. The Agent declares the intended `axis`; the host marks a trial `confounded` if unrelated axes or evaluator settings changed. Keep this open to new mechanisms: the axis is an auditable description, not a closed model enum. Compare a structural candidate with a compute-matched tuned baseline before concluding that the structure caused a gain.

### 4. Field availability is checked by name, not typed, time-safe modeling roles — high

**Local evidence.** A snapshot must provide `fields` as names and `capabilities` as strings ([engine.py](../../src/model_evo_harness/engine.py), lines 44–60). Family/method readiness is set membership over those capability strings ([catalog.py](../../src/model_evo_harness/catalog.py), lines 337–373). The optional `feature_schema` is described but not enforced ([adapter-contract.md](../adapter-contract.md), lines 37–41). A declared `event_sequence` therefore does not by itself prove legal event cutoff, entity join, ordered masks, cardinality or sufficient history. The same applies to item–entity links or coupon cost provenance.

**Upstream evidence.** RecBole's [atomic files](https://recbole.io/docs/user_guide/data/atomic_files.html) separate interactions, users, items, knowledge triples, links and social edges, with token, sequence and continuous field types; [data settings](https://recbole.io/docs/user_guide/config/data_settings.html) determine loaded fields and sequence length. **Inference:** a proposed graph, sequence or feature-interaction experiment may be inapplicable even when an umbrella capability is true.

**Minimal completion.** Let adapters declare only the roles relevant to their task: entity keys, feature type/cardinality/shape, source table, event and availability time, missingness, label/propensity provenance and legal joins. Validate a candidate's required roles and tensor signature against this contract before spending a training trial. For a fixed coupon RCT, keep this compact: treatment, pre-treatment covariates, outcome horizon, known cost semantics and randomization unit are enough. Do not import RecBole's file format as a mandatory dependency.

### 5. Pipeline and decision hypotheses are mostly guidance until a host adapter executes them — medium-high

**Local evidence.** `decision_mapping` requires a `decision_rule_adapter` capability ([supplemental_families.json](../../src/model_evo_harness/data/supplemental_families.json), lines 15–25). The [decision guide](../../src/model_evo_harness/knowledge/decision_mapping.md) correctly prescribes frozen predictions, cost and budget checks, paired uncertainty and one final holdout (lines 3–17), but no generic rule executor or value evaluator lives in the harness. Model references likewise explicitly exclude an ANN index, trainer or coupon policy ([models.md](../models.md), lines 63–70). A single model card cannot test multi-channel candidate coverage or a long-history selector without pipeline inputs.

**Upstream evidence.** Wang separately lists [other retrieval channels, prediction score fusion, SIM history, reranking constraints and diversity](https://github.com/wangshusen/RecommenderSystem#工业界的推荐系统). Its [reranking notes](https://raw.githubusercontent.com/wangshusen/RecommenderSystem/main/Notes/06_Rerank.pdf) discuss feasibility and diversity beyond pointwise scores. **Inference:** with a fixed predictor, decision or pipeline mechanics may be the bottleneck; training another network can be a low-information trial.

**Minimal completion.** Define two optional host candidate operations, each with an unchanged control: (a) a candidate-set union/filter with fixed total K, deduplication and unchanged downstream ranker; (b) a frozen-score threshold, value fusion or rule-feasible reranker with identical scored units. Require candidate-set provenance, eligibility and constraints; report both predictive and business metrics. Keep coupon action policy distinct from slate ranking and require a valid randomized/off-policy value estimator where business-value claims need one.

### 6. Distinct graph propagation and graph self-supervision are absent as runnable local mechanisms — medium

**Local evidence.** [Collaborative retrieval](../../src/model_evo_harness/knowledge/collaborative_retrieval.md) currently selects UserCF, ItemCF, Swing, FunkSVD and BiasSVD (lines 17–25); [item representation](../../src/model_evo_harness/knowledge/item_representation.md) selects Item2Vec and EGES (lines 17–22). These are useful references but do not implement normalized multi-hop user–item propagation or perturbed-graph contrastive views. The new [exploration strategy](../../src/model_evo_harness/knowledge/exploration_strategy.md) explicitly labels LightGCN-style and SGL-style tests as design requiring a graph builder (lines 15–17).

**Upstream evidence.** RecBole's [LightGCN](https://github.com/RUCAIBox/RecBole/blob/master/recbole/model/general_recommender/lightgcn.py) propagates embeddings through a normalized interaction graph; [SGL](https://github.com/RUCAIBox/RecBole/blob/master/recbole/model/general_recommender/sgl.py) adds graph perturbations and self-supervised terms. They are not aliases of Item2Vec or EGES. **Inference:** this is a real non-overlap, but not a blanket priority for a coupon table with no item graph.

**Minimal completion.** First measure sparse and tail retrieval gaps against factorization/ItemCF using training-only edges. Only if the graph hypothesis survives should an adapter provide graph construction and a compact direct-framework LightGCN reference; test SGL as a separate loss/view ablation. Maintain time cutoff, full-catalog evaluator and K. Avoid listing graph models as ready without the edge contract.

### 7. Negative-sampling semantics have been corrected; execution still needs provenance — medium

**Local evidence.** The current `hard_negative_mining` pattern requires implicit feedback, a declared sampler and item catalog, while stating that exposure logs are needed only to claim observed non-response ([training_patterns.json](../../src/model_evo_harness/data/training_patterns.json), lines 40–46). The [sampling guide](../../src/model_evo_harness/knowledge/sampling_and_hard_examples.md) distinguishes observed non-response, sampled unobserved, in-batch and mined items, and says absent impressions do not block all retrieval tests (lines 5–19). This addresses the overstrong wording in the older [review](recbole-wang-review.md), lines 9–11. The host still constructs the actual negative pool and sampling probabilities ([models.md](../models.md), lines 48–61).

**Upstream evidence.** RecBole distinguishes [implicit versus labeled data](https://recbole.io/docs/user_guide/data/label_of_data.html), [training sampler settings](https://recbole.io/docs/user_guide/config/training_settings.html) and [evaluation sampling modes](https://recbole.io/docs/user_guide/config/evaluation_settings.html); Wang indexes a [retrieval-positive/negative lesson](https://github.com/wangshusen/RecommenderSystem/blob/main/Slides/02_Retrieval_07.pdf). **Inference:** an exposed but unclicked item may be useful for an exposure-conditioned ranking target, yet may alter broad retrieval semantics. Its use is a hypothesis about the target and logging process, not a universal rule.

**Minimal completion.** Host receipts should identify label type and source, eligible sampling pool, sampler version/distribution, false-negative checks and fixed evaluator. Compare random/in-batch with one hard mixture under matched count and full/fixed-catalog evaluation. Never relabel an unobserved sampled item as an observed negative, nor a randomized coupon non-response as a negative treatment effect.

### 8. The score leader is an exploratory champion, not a final claim — medium

**Local evidence.** `best_id` updates on the directionally better validation `score` ([engine.py](../../src/model_evo_harness/engine.py), lines 383–392). This is appropriate for exploration; [adapter-contract.md](../adapter-contract.md) explicitly assigns paired intervals, guardrails and final holdout to the host (lines 37, 120–122). The [exploration strategy](../../src/model_evo_harness/knowledge/exploration_strategy.md) already calls it an exploratory champion (lines 27–31).

**Upstream evidence.** RecBole's [significance-test workflow](https://recbole.io/docs/user_guide/usage/significance_test.html) exists to compare runs rather than infer from a lone larger number. **Inference:** repeatedly selecting on a validation score creates selection bias; an independent result needs a protected evaluation design, with correct pairing/randomization unit for the host task.

**Minimal completion.** Surface `best_id` as `exploratory_champion_id` in reports or clearly label its status; do not break journal compatibility solely to rename a key. Require the host's paired-difference interval, predeclared guardrails and single final holdout result before any UI/API claims `validated_improvement`. This is a reporting and integration boundary, not a defect in picking the next candidate by score.

### 9. Cross-scene positioning exceeds currently runnable stage coverage — medium

**Local evidence.** `feature_interactions` and `sequence_ranking` list ranking/policy stages ([catalog.json](../../src/model_evo_harness/data/catalog.json), lines 183–190 and 229–237), while the search stage appears in `generative_applications`, which has no source models and needs `generative_targets` (lines 449–468). The readiness filter follows these stage declarations ([catalog.py](../../src/model_evo_harness/catalog.py), lines 337–373). On the present catalog, a search snapshot with broad declared capabilities yields no ready method cards. The 44 reference implementations therefore do not by themselves constitute a search-model experiment system.

**Upstream evidence.** RecBole's [model introduction](https://recbole.io/docs/user_guide/model_intro.html) is principally recommendation-oriented; Wang's course covers recommendation retrieval/ranking/slate systems. **Inference:** their sources can inform search ranking but do not define query–document labels, query grouping, retrieval corpus or auction contracts for this harness.

**Minimal completion.** State the cross-scene goal as an adapter goal, then add a search adapter with query–document roles, query-grouped splits, corpus/candidate protocol and NDCG/recall semantics before widening readiness. Advertising likewise needs impression, auction or cost contracts according to its actual objective. Avoid changing stage tags simply to make cards appear ready.

## Recommended sequence

1. Wire the new [exploration strategy](../../src/model_evo_harness/knowledge/exploration_strategy.md) into the Agent context (already done in [catalog.py](../../src/model_evo_harness/catalog.py), lines 45–50), then make diagnostic reports and their evidence keys available from host adapters. This should raise the fraction of trials that test a measurable bottleneck.
2. Add host trial receipts for protocol identity, actual changed axis, cost and support. Keep `best_id` as a labeled exploratory score leader; independently validate the selected candidate in the host.
3. Implement only the stage-specific mechanism that a real adapter and observed residual justify: graph retrieval, channel union, long-history selection, constrained decision, or another open hypothesis. A broader card list without data and controls would reduce exploration efficiency.

## Source limitations

The RecBole documentation viewed here identifies itself as version 1.2.1; GitHub links point to the live official `master` and may move. Wang's repository index and linked slide/notes paths were checked; individual PDF details are used only where the linked official material or the prior pinned local review supports them. This audit did not run a host dataset or compare algorithms; expected value and priority are engineering judgments.
